Universal Bot Platform

Топология бот-платформы

Кто с кем связан и куда физически идут запросы: bot, backend, worker, admin- и mini-app, Redis, PostgreSQL — по коду в docker-compose.yml, nginx-конфигам фронтендов и клиентам backend/bot.

REST API внутр. переадресация nginx→backend Redis (очередь / лимиты) PostgreSQL (SQL) внешний MAX API / webhook стрелка = кто инициирует соединение

Связи подробно

СвязьПротокол / эндпойнтАутентификацияКомментарий
браузер → frontend-admin → backend HTTPS → /api/*, /ws/* Bearer JWT (access) + refresh в HttpOnly-cookie nginx контейнера форвардит /api и /ws на backend:8000 по внутренней docker-сети (см. frontend-admin/nginx.conf); в проде внешний nginx может проксировать эти пути в backend напрямую, минуя контейнер.
MAX-клиент → frontend-miniapp → backend HTTPS → /api/* (вкл. /api/ws/chat) initData (подпись MAX) → POST /auth/init-data/validate → JWT Тот же паттерн: nginx мини-аппа форвардит всё под /api на backend:8000.
MAX-клиент ↔ платформа MAX обычный чат, открытие мини-аппа — Вне нашей системы — стандартный протокол мессенджера MAX.
платформа MAX → bot webhook POST подписка через bot.subscribe_webhook() Публичный URL вебхука выходит наружу через тот же reverse-proxy, на порт :7800.
bot → платформа MAX MAX Bot API — отправка сообщений/вложений токен бота из тома bot-secrets Исходящий вызов наружу, в обход нашего reverse-proxy.
bot → backend POST /api/messages/ingress
POST /api/messages/ai/callback		 X-Bot-Token, X-Bot-Runtime-Token, X-Bot-Slug Синхронный REST на BOT_INTERNAL_API_URL; так входящие сообщения пользователя попадают в backend.
backend → PostgreSQL SQL (SQLAlchemy) — Все tenant-owned сущности скоуплены по bot_instance_id.
backend → Redis INCR/EXPIRE (rate-limit), SET NX EX (идемпотентность) — Идемпотентность защищает /messages/ingress от повторной обработки одного вебхука (окно 3600с).
worker → PostgreSQL SQL, джобы APScheduler — push_outbox, monitoring, admissions_monitoring, sync рейтинга поступления.
worker → Redis RPUSH {system}:{bot_slug}:push:queue, лок SET NX EX — Берёт неотправленные строки push_outbox из Postgres и кладёт в очередь; лок нужен, чтобы несколько реплик worker не задублировали доставку.
bot → Redis чтение той же очереди push:queue — Забирает подготовленные push-сообщения и рассылает их через MAX Bot API — отдельный от синхронного ingress путь.

Слои, не показанные как отдельные узлы: общие docker-volume — uploads-data (файлы, backend + worker), bot-secrets (секреты бота: read-write у backend, read-only у bot), db-data, redis-data.

Dev-режим (docker-compose.dev.yml): reverse-proxy отсутствует, все порты торчат на localhost напрямую — backend :8000, bot :8080, admin :5173, miniapp :5174, Postgres :5432, Redis :6379.
