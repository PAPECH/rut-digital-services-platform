# Проверка собственного API

## Переданные материалы

- `openapi.json` — контракт OpenAPI 3.1.0, сформированный запущенным FastAPI-приложением;
- `DATA-API.yaml` — обязательные проверки основного сценария;
- `test-data.json` — демонстрационные значения и источники динамических идентификаторов.

## Адрес

Базовый HTTPS-адрес: `https://app.rut-platform.ru`.

API-маршруты имеют префикс `/api`. Проверка доступности backend выполняется запросом `GET /healthz`.

- OpenAPI: `https://app.rut-platform.ru/openapi.json`;
- Swagger UI: `https://app.rut-platform.ru/docs`.

## Авторизация

Пользователь и сотрудник входят через MAX. Отдельные постоянные тестовые логины и пароли не используются.

- mini-app передаёт подписанный `initData` в `POST /api/auth/init-data/validate`;
- backend проверяет подпись MAX и выдаёт краткоживущий Bearer-токен;
- административный доступ создаётся по ссылке-приглашению из `JURY_GUIDE.md`;
- запросы к данным конкретного бота содержат заголовок `X-Bot-Slug`;
- рабочие токены, ключи и пароли не входят в комплект исходного кода и материалы подачи.

`initData` имеет ограниченный срок действия, поэтому его получают непосредственно перед технической проверкой, открыв соответствующее мини-приложение внутри MAX.

## Порядок проверки

1. Пройти основной маршрут по `JURY_GUIDE.md`. Это основной способ продуктовой проверки.
2. Для проверки HTTP-контракта получить пользовательские сессии ботов `krutya_bot` и `rut_rector_bot` через MAX.
3. Перейти по приглашению и получить административную сессию для `rut_rector_bot`.
4. Выполнить проверки из `DATA-API.yaml` по порядку, передавая значения, полученные на предыдущих шагах.
5. При повторном прохождении создать новую заявку и выбрать свободный талон.

## Ожидаемый итог

Проверка подтверждает полный обмен данными между компонентами:

1. студент получает дерево групп и расписание;
2. студент получает опубликованную форму и создаёт заявку;
3. секретарь видит заявку, переводит её в работу и назначает свободные талоны;
4. заявка завершается, а уведомление доставляется студенту в MAX;
5. уточняющий вопрос появляется в тикетах, ответ сотрудника возвращается в чат MAX.

## Безопасность тестовых данных

Используются демонстрационные формулировки из `test-data.json`. Не вводите реальные паспортные данные, документы или иные избыточные персональные сведения.
